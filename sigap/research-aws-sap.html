How AWS and SAP say to build this

03

The piece that did not exist when we planned AWS · blog

AWS now ships a container image, at no cost, that exposes SAP OData as MCP tools and runs on AgentCore Runtime. This is the most important finding.

What it does

  1. Discovers which OData services exist, through a catalog discovery tool. Two modes, remote catalog or local.
  2. Pulls service hints from configuration held in S3, for context on how a given service behaves.
  3. Calls CRUD operations on business objects: sales orders, purchase orders, and so on.
  4. Performs the OData call over whichever connectivity path is configured.

Three connectivity topologies

TopologyPathWhere traffic goes
SAP BTP API ManagementHTTPS, OAuth 2.0Egresses to internet, TLS
SAP Cloud ERP Private (RISE on AWS)VPC Peering or Transit GatewayStays on the AWS backbone
SAP ERP on AWSSame VPC or cross-VPCNever leaves AWS

Authentication is two-sided

Through AgentCore Identity. Inbound, MCP client to server: IAM, Cognito, Microsoft Entra ID, or Okta. Outbound, server to SAP: OAuth 2.0.

Stated limits

The page documents OData V2 compatibility and does not mention V4. Service hints are a manual S3 configuration unless the remote catalog is reachable.

04

The closest published build to ours AWS · blog

AWS for Industries published a procurement agent against SAP S/4HANA on EC2. It is the nearest thing to SIGAP in the public record, which makes both its choices and its omissions useful.

Shape

  • Orchestration. Strands Agents SDK on AgentCore Runtime, containers on ECS/Fargate.
  • Data plane. S3 holds structured procurement data, Glue Data Catalog holds metadata, Athena runs the SQL, OpenSearch does document search.
  • SAP write path. AgentCore Gateway gives an MCP bridge, a Lambda executes the MCP client call, Secrets Manager holds the credentials.
  • Edge. Cognito for JWT and role-based access, WAF, API Gateway for a WebSocket so replies stream.
  • Eight tools, including schema lookup, natural language to SQL, financial analysis, quality metrics, compliance validation against REACH, RoHS, CMRT and RBA, RFQ creation through SAP OData, and a sandboxed visualisation tool.
Two things it does not have

No approval gate. The article describes RFQ creation as user-directed tool invocation and documents no review or authorisation step before a write reaches SAP.

No stated evaluation. Outcomes are given qualitatively, "reduces cycle times", "cost savings". No benchmark, no metric, no dataset.

05

The SAP side: Joule, the Agent Hub, A2A SAP · learning

SAP does not expose its agents directly. Its published pattern is A2O, agent-to-orchestrator: an external agent talks to Joule, and Joule talks to SAP agents.

LayerRole
JouleThe central orchestrator. Governs how agents interact and how tasks are planned and delegated
Agent HubProtocol adapter. Translates A2A and MCP into SAP's internal agent APIs, and enforces security, licensing and metering centrally
A2ASAP's preferred standard for agent to agent work. Discovery by role or capability, task delegation, artifact exchange
MCPThe universal interface for an agent to reach tools and data

A pro-code agent that runs in its own runtime integrates through A2A. That is exactly the shape of a system like ours.

Timing worth knowing

General availability of the enhanced A2A capabilities in Joule is reported as Q4 2026. Demo day is 31 October 2026, so this is a roadmap item to speak about, not one to depend on.

06

AgentOps: how AWS says to evaluate and operate an agent AWS · blog

The richest source, and it lands directly on our largest known gap.

Evaluation has four levels, not one

LevelWhat is judgedExample metrics
Tool (span) One tool call Deterministic tools: unit tests, latency, error rate. Model-backed tools: correctness, relevance. Plus tool selection accuracy and parameter extraction
Turn (trace) One question and its answer Correctness, faithfulness, relevance, coherence, instruction following
Session outcome Did the whole conversation achieve the goal Task completion rate, goal accuracy, efficiency, memory consistency
System The service End to end latency, throughput, tool error rate, cost per task, compliance adherence

Three modes, each with a gate

ModeRunsGate
On-demandDuring development, against a reference dataset with ground truthMust pass before pre-production
CI/CDAutomated, pre-productionMust pass before production
OnlineContinuously, on sampled live trafficAutomated rollback on degradation

Authorisation happens at four checkpoints

Tool access is evaluated deterministically with Cedar policy, enforced through AgentCore Gateway, on top of least-privilege IAM.

Observability has four instrumentation layers

  1. Agent and framework. Reasoning steps, model calls, tool invocations.
  2. Service. Memory reads and writes, gateway auth, identity policy evaluation.
  3. Infrastructure. Container and Lambda metrics.
  4. Application. Business metrics across a multi-agent system.

Correlation uses W3C Trace Context for a shared trace id across agents, and OpenTelemetry Baggage to carry a session id across separate traces. Signals AWS calls out specifically: token spend per session, per agent and per task; memory extraction quality; toxicity, bias, hallucination rate and PII leakage.

Four repositories, not one

Infrastructure, agents, tools and the consuming application are versioned separately. Tools get their own CI/CD and are deployed behind MCP servers. Agent versions are immutable, promoted by alias, and rolled back by pointing the alias back.

What this means for SIGAP ours

The shape we chose matches what both vendors publish. Two pieces are worth adopting, one gap is now clearly defined, and two of our decisions look better than the closest published build rather than merely different.

Their patternSIGAP todayVerdict
AgentCore Runtime hosts the orchestration loop graph.py owns the loop Aligned. AWS-PLAN.md §2 already chose Runtime over Managed Harness for this reason
AWS for SAP MCP Server for OData reads clients/ is a hand-rolled connector Reconsider. This shipped after we wrote ours. Free container, catalog discovery and OAuth already handled
Gateway plus Lambda for SAP writes sender.py posts directly, handles CSRF Keep for now. Ours works and is auditable. Gateway's gain is MCP tool schemas for free, not correctness
AgentCore Memory conversations and messages in SQLite Keep ours. Ours is owner-scoped and part of the record. Memory is agent working context, a different job
AgentCore Identity core/identity.py, HMAC sessions Keep ours, as already decided. Theirs authenticates an agent to a tool, ours authenticates a buyer to an approval endpoint
Cedar policy on tool access Role caps and a cost cap, in business terms Real gap, different layer. We authorise people. Nobody authorises the agent, per tool
Four-level evaluation hierarchy Absent Biggest gap, and now it has a shape. This is PLAN item 7
W3C Trace Context, OpenTelemetry core/trace.py plus the steps table Partly aligned. We record every step with provenance. We do not export OTel, so nothing correlates outside our own database
Online evaluation on sampled traffic Absent Post-demo. Needs production traffic to exist first
SAP A2A through Joule Not addressed Aligned by accident. We are a pro-code agent in our own runtime, precisely the A2A shape SAP documents. One slide, not code

Where we are ahead of the published reference

Both are worth saying out loud, because the nearest comparable build does not do them.

  1. Every action waits for authority it is entitled to. Bounded autonomy to Rp 50m, role caps checked server-side, one-shot approvals, idempotent actions. The Smart Procurement Assistant writes an RFQ into SAP with no documented approval gate.
  2. Every figure carries where it came from. An origin label on every tool result, and a calculator that refuses to produce rupiah when its inputs are not trustworthy. Neither published architecture labels provenance at all.

What to do about it

WorkWhy now
1Build the eval suite against the four levels, starting at tool and turn levelAlready PLAN item 7, now with a published shape to copy
2Evaluate AWS for SAP MCP Server against clients/ before writing more connector codeIt may delete work we have not done yet
3Emit OpenTelemetry spans from core/trace.py, carrying a session idCheap, and it makes the trace legible outside our own interface
